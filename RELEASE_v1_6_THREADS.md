## Automated daily behavior (after OAuth)

- [Threads Nurture workflow](.github/workflows/threads-nurture.yml) cron at 09:45 Vietnam time, best effort.
- Planner maintains a draft queue, originally 14 days; when the queue drops below 6 and Groq is configured, it attempts to generate one new editorial post.
- `threads.publisher` checks `THREADS_ACCESS_TOKEN`, `THREADS_EXPECTED_USERNAME`, `THREADS_PUBLISH_ENABLED=true`, then confirms Meta /me ID and username.
- Backend only claims 1 due editorial post, performs Meta `/me/threads` + `/me/threads_publish` flow, stores confirmed remote ID.
- Ambiguous API responses are marked `uncertain`, never retried automatically; rate limits, access revocations stop publishing.
- Optional `threads.insights` stores real analytics only when the Meta token grants the insights scope and the API returns a complete response.

## Pending before any public post or Affiliate account

1. The human owner must create/verify a **real Threads account** under their control, and approve Meta OAuth. This cannot be completed via the current GitHub/Supabase connector access.
2. A Meta app with Threads use case and valid user token must be obtained. Token and expected username are written to **GitHub Secrets**, not code or chat.
3. The human owner explicitly enables `THREADS_PUBLISH_ENABLED=true` after verifying the correct account. Without it, live publishing remains disabled.
4. Shopee has **not been verified to accept Threads** as an affiliate registration social account; check updated terms and the review outcome. KOC approval is not guaranteed based on a few days of posts.
5. Shopee's identity, tax/payment/account details require legitimate owner authorization and verification; the Agent may automate permitted operations only after integration is granted.
